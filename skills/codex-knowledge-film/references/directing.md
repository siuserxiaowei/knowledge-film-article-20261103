# 从参考到分镜

先用一句话写“观众看完能解释什么”。给抽象概念找到可叫出名字的东西和动作：人走过出口、杯里的水被分走、书被手机通知打断。对象、动作、量与结果应可见；题名、提问、结论不必硬配动画。

参考视频先分析主题、每幕发生的事、对象变化、文字停留、镜头推拉和声音落点。能读取字幕/转录时用可用连接器或remio；不能访问原片时说明实际看到的材料范围。抽帧用于研究与比较，不默认进入新片。

采用配色/节奏时，为当前文稿重新画场景，保留原作者、链接和素材许可。不搬参考Skill例片、原音轨、账号标识或独特镜头组合来宣称原创。

## 工作记录

- `content/facts.md`：论点、事实/出处、机制示意、口语改写与不确定点。没有依据的演示数字标示意。
- `content/storyboard.md`：每句的场景、字幕/口语、主体、动作、观众理解的因果、声音；多句可共用同一场景。先规划，再用实际声音校准时间。

## 检查

1. 遮住字幕，能说出是什么、在做什么吗？若只认得圆/线，需要更具体的对象。
2. 同一场景撑几句，每句改变解释需要的一处。结尾可回到开头展示机制改变后的结果。
3. 字幕区干净，中文句子可读，使用完整字库；查看原尺寸帧和缩小画面。
4. 先做难镜头，同点截帧修改至少两轮，再检查开头20–30秒；轮数不保证质量。
5. queue与attention是两份独立示例，不是全部题目的万能画面。新题目在 `src/Scenes.tsx` 实现专用组件并登记 `SUPPORTED_KINDS`；模板会拒绝未实现的custom/unknown场景。图表用于真正需要比较的量。

默认暖黑背景、金色强调、红色代价、象牙白事实，16:9/1080p/30fps；用户要求优先。竖屏重新排版，不机械裁切横屏。不要承诺固定耗时、完全自动化或零成本。

## 注册新场景

模板的注册分两处，不能只改JSON：

1. 在 `src/Scenes.tsx` 中实现该题目的React/SVG组件，或从单独的tsx文件导入；使用scene、t、duration与theme驱动内容和动画。
2. 在 `SUPPORTED_KINDS` 原名单后追加自己的kind，例如 `reading-interruption`，保留其他已实现条目。
3. 在 `SceneArt` 内增加对应分支，例如 `if(scene.kind==='reading-interruption') return <ReadingInterruption scene={scene} t={t} duration={duration} theme={theme}/>;`，前提是组件已经实现。
4. 在film.json的场景中使用同一个kind，再prepare/check，抽关键帧检查对象与动作。只登记名单、仍返回占位画面不算实现。
